## Problem Statement
지금 앱은 "폼 + 옆에 붙은 AI"다. 에이전트 뼈대(툴 9개, `runAgent` 툴 호출 루프, `STAGE_GOALS`)는 있지만 AI는 읽고 말하기만 하고, 사용자가 버튼을 눌러야 움직인다. 후보 탐색·순위는 전부 결정론적 코드다. 수업 발표에서 "이건 에이전트다"라고 보여 줄 장면이 없다.

## What Makes This Cool
5단계 관심 단지 2~4개를 두고 분야 전문가 AI 5명이 각자 1순위를 주장하고 서로 반박한다. 화면에는 주장마다 코드가 실제 데이터와 대조한 **검증됨 ✓ / 기각 ✗** 표시가 붙는다. 최종 결론은 "당신 우선순위로는 A, 대신 포기하는 것은 X".
- 사용자가 원한 장면: `교통 AI: 출퇴근에는 @가 가장 좋다 / 교육 AI: @가 초품아 … ⬇️ 토론 요약: a b c가 좋다`
- 차별점: 환각 없는 멀티 에이전트 토론. AI는 주장·반박·요약만, 숫자와 순위는 코드.

## Constraints
- 원칙 1: 금액·순위 계산은 코드. LLM은 숫자를 만들지 않는다.
- Gemini 무료 요금제(gemini-3.5-flash-lite), 프로젝트 전체가 분당·하루 한도를 공유. 429 → 503 `llm_quota`.
- 원칙 9: LLM에는 식별 정보 없이 단지 지표만 보낸다.
- 5단계 기존 원칙: "어느 단지를 사라고 정하지 마세요".
- `compare_complexes` 상한 4개. 데이터에 없는 것: 단지 내 편의시설, 개발 계획, 금융(은행) 위치. 학원 수는 상가정보 업종 코드로 셀 수 있음(2026-11-28 확인).

## Premises (사용자 동의, 2026-11-27)
1. 토론자는 분야 전문가 패널(교통·교육·예산·생활·장기가치/정비사업). 각자 자기 분야 데이터 조각만 받고, 데이터에 없는 것은 말하지 못한다.
2. 적대적 = 2라운드: ① 각자 1순위 + 근거 ② 다른 전문가의 픽을 자기 데이터로 반박.
3. 최종 순위는 코드: 주장 검증(틀린 주장 버림) + 2·3단계 중요도로 가중 투표. AI는 요약 문장만.
4. 결론은 "사라"가 아니라 "내 우선순위로 보면 A, 대신 아쉬운 점은 X"(초안의 "포기하는 것"을 화면에서는 "아쉬운 점"으로 부른다).
5. 1회 ≈ 호출 11회. 입력 해시 캐시, 사용자당 하루 횟수 제한. 대상은 관심 단지 2~4개.

## Landscape (웹 검색, 2026-11-27)
- 토론은 동조를 부른다: 라운드가 쌓일수록 다수 쪽으로 쏠리고 정확도가 떨어지기도 한다 (arXiv 2605.00914, 2509.05396, 2506.01332). 출처를 알면 편향 (2510.07517, 익명화 권장).
- 성능 이득은 대부분 투표에서 나온다 (Debate or Vote, arXiv 2508.17536; 2311.17371; 2310.01798).
- 반영: **픽은 1라운드 직후 잠금**(반박 뒤 변경 불가), 반박 라운드에는 다른 전문가 주장을 **익명**으로 준다, 순위는 **코드 가중 투표**.
- 핵심 통찰: 이 앱에서 토론의 목적은 정답 수렴이 아니라 **트레이드오프를 드러내는 설명**이다. 결정은 투표가 한다. 그래서 문헌의 실패 모드가 결정을 오염시키지 못한다.

## Approaches Considered
- A) 한 번 호출 패널: 호출 1회로 5명 목소리를 JSON 하나에. 진짜 멀티 에이전트가 아니라 발표에서 약해서 탈락.
- B) 독립 전문가 5명 + 픽 잠금 + 반박 1라운드: **선택**.
- C) 단지별 변호인: 법정형이지만 분야 전문가 장면("교통 AI/교육 AI")이 사라져서 탈락.

## Recommended Approach: B

### 전문가 = 역할 프롬프트 + 데이터 조각 + 출력 스키마
같은 모델을 5번 부르고, 아래 셋만 바꿔 끼운다. 전문가에게 툴은 주지 않는다. 코드가 `compare_complexes`를 한 번 돌려 조각을 나눠 준다(호출 절약, 엉뚱한 툴 호출 방지).

| id | 이름 | 받는 지표 (모두 코드가 계산) | 발언권 출처 |
|---|---|---|---|
| transit | 교통 | 역 이용량, 역·정류장 거리, 노선 수·환승, (통근은 표에만) | 2단계 대중교통 이용 여부 |

| budget | 예산 | 총 필요 금액, 필요 대출·월 상환액, 시세 대비 위치, 예산 비율 | 고정 최대(5) |

| value | 장기가치 | `approval_year`, `floor_area_ratio`, `land_share_m2`, `redevelopment` | 3단계 정비사업 관심 |

설정 표 하나(`lib/agent/debate/panel.ts`)로 둔다. 패널 변경 = 표 한 줄 수정.
"표 무게"는 화면에서 **발언권**이라고 부른다(1~5, 점 5개 미터). 집계 단위는 "점".

### 전문가별 지표 보완 (2026-11-28 사용자 요청)
원칙: 누구나 아는 지표(통근이 짧다)보다 전문가라서 보는 지표로 논쟁하게 한다. 지표마다 "높을수록 좋음/낮을수록 좋음" 방향을 코드에 두고, 검증은 지금처럼 "그 지표에서 실제 1위/꼴찌인가"로 한다. 모든 값은 수집기·`lib/calc`가 만들고 LLM은 숫자를 쓰지 않는다.

### 흐름
1. **준비(코드)**: `compare_complexes(favorite ids)` 1회. 전문가별 조각 생성. 입력 해시로 캐시 조회.
2. **1라운드(병렬 5회)**: 각자 `{pick, claims:[{complex_id, metric, direction:"best"|"worst", says}]}`. 픽 잠금.
3. **반박 라운드(병렬 5회)**: 다른 전문가의 픽·검증된 주장을 익명(전문가 A~D)으로 받아 `{target, complex_id, metric, direction, says}`. 자기 필드로만 반박.
4. **검증(코드, 순수 함수)**: 주장마다 ① `metric` ∈ 그 전문가의 필드 ② `complex_id` ∈ 비교 대상 ③ `direction`이 실제 비교 순위와 일치(예: "best"라면 그 지표에서 정말 1위). `says`에 숫자가 있으면 기각. **숫자는 화면에서 코드가 데이터로 렌더**("역 320m")하므로 LLM은 숫자를 쓸 필요가 없다.
5. **집계(코드, 순수 함수)**: 검증된 픽 × 발언권 합산, 동점은 `fit_score`.
   - 검증된 픽: 그 전문가의 1라운드 주장 중 픽 단지를 근거로 한 주장이 하나 이상 ✓일 때만 센다. 모두 ✗이면 그 전문가 점수는 0(Figma 예외 `근거가 모두 데이터와 다름`).
   - "대신 아쉬운 점": 1위 단지가 최하위인 지표(compare 결과의 `best`로 계산), 최대 2개.
   - "이렇게 보면 달라져요": 전문가 한 명의 발언권을 5로 올려 다시 집계했을 때 1위가 바뀌는 경우만 보여 준다(코드 재집계, LLM 호출 없음).
6. **요약(1회)**: 검증된 주장 + 집계 결과만 받아 3~5문장. 숫자 금지, 실패하면 템플릿 문장으로 대체.

### 화면 (Figma 팀 파일 Design System 페이지 · 섹션 `09 Stage5 Redesign`)
프레임(노드 ID): 토론 완료 `90:374` · 토론 전 `95:799` · 토론 중 `95:920` · 예외 `95:1093` · 모두 펼침 `117:981`. 화면 숫자는 모두 예시 값이다.
- **전문가 의견 = 한 줄 목록 + 펼치기**: 한 줄에 아바타 · 발언권(점 5개) · 1순위 단지 · 핵심 근거 한 줄 · 확인된 주장 수(✓2 · ✗1). 하나씩 펼치는 게 기본이고 "모두 펼치기"도 있다.
- **펼침 순서**: 한마디(문장 1개, 숫자 없음) → 전문가별 상세 표(A/B/C 값, 가장 나은 값 굵게) → 근거(주장 한 줄 + 확인된 값 칩, 틀린 주장은 ✗와 실제 값) → 반박 스레드 → 아쉬운 점.
- **반박 스레드(채팅형)**: 맨 위 안내 한 줄("교육 전문가가 예산 전문가의 선택에 반박했어요"), 상대 전문가는 왼쪽 회색 말풍선(자기 1순위를 말함), 이 전문가는 오른쪽 초록 말풍선("그런데 …"로 시작). 이름은 말풍선 위, 확인된 값은 말풍선 아래 칩. LLM에는 상대를 익명으로 주지만 화면에는 이름을 보여 준다.
- **결과 카드**: 내 우선순위로 보면 1위 · 점수 막대(단지 색) · 점수 내역("A = 교통 4 + 예산 5") · 대신 아쉬운 점 · 이렇게 보면 달라져요 · AI 요약 · 다시 토론하기 · 오늘 남은 횟수.
- **항목별 비교 표**: 전문가 분야와 같은 다섯 묶음. 전문가 상세 표의 지표를 모두 담는다(생활은 시설 합계만, 유형별은 생활 전문가 펼침에서). 통근 시간은 이 표에만 있다. 가장 나은 값은 굵게 + "가장 유리". 시세 흐름은 "참고"로 표시만.
- **더 궁금한 점 물어보기**: 질문 칩 3개를 누르면 기존 AI 상담(`AssistantPanel`, `/api/chat`)으로 이어진다. 답변으로 순위는 바뀌지 않는다.
- **단지 색**: A 파랑 · B 보라 · C 주황 · D 분홍(변수 `complex/a~d`). 배지·막대·표 열 머리에 같이 쓰고, 항상 짧은 이름을 붙인다. 초록·빨강은 ✓·✗ 전용.
- **문구**: 해요체, 내부 용어(기각·집계·코드·표 무게) 대신 사용자 말로. 이모지는 ✓ ✗ 🔒만.
- **하루 횟수**: 디자인은 3회 기준(구현 때 확정).
