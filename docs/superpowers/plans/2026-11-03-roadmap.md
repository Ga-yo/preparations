# 내 집 마련 AI 에이전트 — 전체 로드맵

**Spec:** `CLAUDE.md` (프로젝트 루트)

이 문서는 마일스톤 순서와 그 사이의 인터페이스만 고정한다. 각 마일스톤은 시작할 때 별도 상세 계획(`YYYY-MM-DD-mN-*.md`)으로 쓴다.
상세 계획을 뒤로 미루는 이유: M2 이후 작업은 공공데이터 응답 필드에 의존하는데, CLAUDE.md는 필드를 추측하지 말라고 한다. 앞 마일스톤에서 실제 응답을 fixture로 저장한 뒤 그 fixture를 근거로 쓴다.

## 결정 사항 (승인 필요)

| # | 결정 | 이유 |
|---|------|------|
| D1 | 원칙 10("시중 대출상품을 매번 조회")은 **금감원 금융상품한눈에 API를 매일 배치로 `loan_products`에 적재하고, 예산·추천 툴이 호출될 때마다 DB를 새로 조회**하는 것으로 해석한다. 캐시하지 않고, 결과에 `data_as_of`를 붙인다. | 원칙 3(에이전트는 공공 API 실시간 호출 금지)과 충돌하지 않게 하는 유일한 해석. |

| D4 | 단계 입력은 **폼**(구조화, zod 검증, RLS로 직접 저장)으로 받고, 채팅 에이전트는 저장된 값을 툴로 읽어 분석·설명한다. | 에이전트가 사용자 숫자를 받아 적는 단계를 없애 계산 오류와 PII 전송을 줄인다. |

## 마일스톤

### M1 — 1단계: 예산 산정 (상세 계획: `2026-11-03-m1-budget.md`)
계산 엔진(대출·취득세·중개보수·예산), 법정동코드·대출상품 수집, 규제 시드, 익명 인증, 에이전트 코어(`/api/chat`), 1단계 화면, CI·수집 스케줄.
**산출 인터페이스:** `lib/calc/*`, `Tool` 계약(`lib/agent/tool.ts`), `runAgent`, `resolveRegion`, collector의 `upsert_rows`/`mark_freshness`.

### M2 — 2단계: 지역·생활 조건
- collector: `jobs/transactions.py` — PublicDataReader `TransactionPrice`로 아파트 매매 실거래가, 수도권 시군구, 최근 24개월 초기 적재 후 매일 최근 2개월 재수집(해제 신고 반영). `source_key`로 upsert.
- 마이그레이션: RPC `region_price_stats(sigungu_prefix text, housing_type text, area_min numeric, area_max numeric, months int)` → 시군구별 중위가·건수·기준일.
- 툴: `get_region_prices`(지역명 → `resolveRegion` → RPC), 예산(M1 `computeBudget` 결과)과 대조해 "예산 내 접근 가능 지역" 표시.
- 화면: 2단계 폼(`condition_sets` 2단계 컬럼) + TIP 4종.

### M3 — 3단계: 주택 조건 구체화 (상세 계획: `2026-11-08-m3-housing-criteria.md`)
- collector: `jobs/complexes.py` — 건축물대장 총괄표제부(법정동)·표제부(미연결 지번만)로 실거래 지번의 아파트 단지를 `complexes`에 적재, `link_transactions_to_complexes(sgg)`로 실거래 ↔ 단지 연결(M4에서 당김). 주 1회.
- 마이그레이션: RPC `complexes_for_conditions(region_codes, area_min, area_max, months)` → 단지 속성 + 단지별 중위가.
- `lib/calc/conditions.ts`: `findConflicts(conditions, budgets, complexes, truncated)` (결정론적: 희망가 > 예산, 희망 면적 대비 지역 중위가 초과, must 조건끼리 충돌 등). LLM은 충돌 코드를 설명만 한다(`deepseek-v4-pro`).
- 화면: 3단계 폼 + 우선순위(must/prefer/ignore) + TIP 6종(spec 예시 ex1·ex2 원문 포함).

### M4a — 4단계: 후보 탐색(기존 데이터) (상세 계획: `2026-11-11-m4a-candidates.md`)
- 기존 단지·실거래 데이터만으로 구현. `search_complexes` RPC 대신 TS 순위 함수 `rankComplexes`(`lib/calc/fit.ts`)로 적합도 순 정렬(M4a-D1).
- 마이그레이션: RPC `complex_trades`(단지 실거래 사례), `complex_monthly_prices`(월별 중위가).
- 툴: `search_complexes`, `get_complex_detail`. `candidates`에는 사용자가 저장한 관심 단지만 기록.
- 화면: 후보 목록·단지 상세·관심 단지 저장/해제 + TIP 6종.

### M4b — 좌표·POI·관리비
- 좌표(D6: VWorld 지오코더 후보), 역·학교 POI, RPC `complex_nearby_pois(complex_id, radius_m)`, K-apt 관리비(M3-D2 재검토).
- 시작 시 키·활용신청·실제 응답 fixture 확인부터.

### M5 — 5단계: 비교·의사결정
- 툴: `compare_complexes(complex_ids: number[])`(`deepseek-v4-pro`), 조건 세트 복제·수정 후 결과 diff(`condition_sets` 새 행).
- 구매 전 확인 체크리스트·다음 절차 안내(정적 콘텐츠).

### M6 — 정비사업 데이터 (데이터 확보 시)
서울 정비사업 정보 → `redevelopment_projects`. 확보 전까지 4·5단계는 "데이터 없음"으로 명시.

## 마일스톤 간 공통 규칙
- 모든 툴 결과는 `{ data, as_of: { [dataset]: 'YYYY-MM-DD' } }` 형태(M1 Task 9 정의).
- 새 데이터셋을 적재하는 job은 반드시 `data_freshness`를 갱신한다.
- 새 화면 입력 항목은 `tips.field_key`로 TIP을 연결한다.
