**PR 분리 (사용자 결정):** M6a(입력 반영 + 중복 질문 정리) → M6b(리포트)

## 배경

1~3단계 폼은 값을 저장하지만 분석·툴·화면 어디에서도 읽지 않는 항목이 있다(2026-11-14 코드 조사).
사용자 결정: 지우지 않고 **모두 결과에 반영한다**. 2·3단계에 면적·방 개수가 중복된다.

## 선행 조건 (원격)

- 원격 `complexes` 15,066행 중 **좌표 0행**(geocode 미실행). 역·학교 거리, 출퇴근 거리, 공원·상가 집계가 모두 좌표를 쓴다 → Actions `run_geocode`를 먼저 실행하고 `data_freshness`로 확인.
- 원격 DB 252MB/500MB.

## 용량 추정 (원칙 11)

| 데이터 | 행 수 × 크기 | 추정 |
|---|---|---|
| 공원 POI (수도권만) | 약 1만 행 × 약 200B (+인덱스) | 약 3MB |
| 상가 집계 (`complexes` 컬럼 4~6개 int) | 15,066행 × 약 24B | 1MB 미만 |

## 입력별 반영 방식 (M6a)

| 입력 | 단계 | 반영 |
|---|---|---|
| 구매 목적 | 1 | 예산 카드·리포트에 표시. 투자/둘 다 → "투자 수익 분석은 제공하지 않음" 안내 코드 |
| 구매 희망 시기 | 1 | 2~3년·미정 → "규제·시세 재확인 필요" 안내 코드, 리포트에 규제 기준일 함께 표시 |
| 부부 합산 소득 | 1 | 예산 카드에 "부부 합산 기준" 표시 |
| 출퇴근 지역 | 2 | 법정동 대표 좌표(그 동 단지 좌표 중심, 없으면 상위 시군구)에서 단지까지 직선거리 → 후보·비교·상세에 표시 |
| 출퇴근 시간 | 2 | M6-D1 환산 → 새 조건 키 `commute_distance_max`(must/prefer/ignore 대상) |
| 대중교통 이용 | 2 | 역 거리 조건 가중치 2 (M6-D3) |
| 학교 중요도 | 2 | 초등학교 거리 가중치 (M6-D3) |
| 편의시설 중요도 | 2 | 상가 집계(반경 500m 생활업종 수) 가중치·정렬 (M6-D3) |
| 선호 환경 | 2 | 공원 인접 → 가장 가까운 공원 거리, 상권 인접 → 상가 집계, 조용한 환경 → "데이터 없음" 안내 |
| 거주 인원 | 2 | 최저주거기준 경고 (M6-D5) |
| 주차 필요 | 2 | 3단계 주차 조건이 비어 있으면 세대당 주차 1대 이상을 prefer로 적용 |
| 지역 선호 이유 | 2 | 리포트에 그대로 표시 (LLM에는 보내지 않음, 원칙 9) |
| 정비사업 관심 | 3 | 비교 표·리포트에서 정비구역 단지를 위로, 4단계 상세에 정비사업 강조 |
