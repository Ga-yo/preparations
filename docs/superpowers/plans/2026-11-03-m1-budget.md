# M1: 1단계 예산 산정 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사용자가 1단계(구매 목적·자금·금융 자격)를 입력하면 결정론적 엔진이 구매 가능 예산·대출 가능액·상품별 월 상환액·부대비용을 계산하고, 에이전트가 그 결과를 데이터 기준일과 TIP과 함께 설명한다.

**Architecture:** 숫자는 전부 `apps/web/lib/calc`의 순수 함수가 만든다. 규제는 `loan_rules`/`regulated_areas`, 상품은 `loan_products`에서 매 호출마다 읽어 엔진에 넣는다. 에이전트(DeepSeek, openai SDK)는 zod로 검증되는 평평한 인자의 툴만 호출하고 결과를 설명한다. collector(Python, uv)가 법정동코드·대출상품을 매일 적재한다.

**Tech Stack:** Next.js 16.4 (App Router, `proxy.ts`), React 19, TypeScript, vitest, zod v4(`z.toJSONSchema`), openai SDK(baseURL `https://api.deepseek.com`), `@supabase/supabase-js` + `@supabase/ssr`, Supabase CLI(로컬), Python 3.13 + uv + PublicDataReader + supabase-py + pytest, GitHub Actions.

**Spec:** `CLAUDE.md`, 로드맵 `docs/superpowers/plans/2026-11-03-roadmap.md`(결정 D1~D5를 전제로 함)

## Global Constraints

- 모델 ID: `deepseek-v4-flash`(기본), `deepseek-v4-pro`(비교·조건 분석: 3·5단계). `deepseek-chat`, `deepseek-reasoner` 사용 금지.
- 금액 계산은 `lib/calc`의 결정론적 코드로만. LLM 프롬프트에 "숫자를 계산하지 말고 툴 결과만 인용" 명시.
- LTV·DSR·한도·스트레스 금리·규제지역은 코드에 하드코딩 금지. DB에서 읽고, 모든 규제 행에 `effective_date`, `source`.
- 에이전트는 공공 API를 호출하지 않는다. 툴 결과에 데이터 기준일(`as_of`) 포함.
- 툴 인자는 1단 스키마, 전부 zod 검증.
- 지역 코드는 LLM이 만들지 않는다. 지역명 → `regions` 조회로 변환.
- 스키마·참조데이터 변경은 `supabase/migrations/*.sql`로만.
- `SUPABASE_SERVICE_ROLE_KEY`는 collector·서버 전용. `NEXT_PUBLIC_` 금지, `apps/web`의 클라이언트 컴포넌트에서 import 금지. 실제 키는 커밋 금지, `.env.example`만 커밋.
- LLM에 이름·연락처를 보내지 않는다. 소득·자산 원값 대신 계산 결과를 보낸다.
- 금액 단위는 원(정수), 면적은 ㎡, 금리는 연 %(예: `4.25`).
- Next.js 16은 학습 데이터와 다르다. 라우트·proxy·server action 코드를 쓰기 전에 `apps/web/node_modules/next/dist/docs/01-app/`의 해당 문서를 읽는다(`01-getting-started/16-proxy.md`, `02-guides/authentication.md`).
- 공공데이터·금감원 API 필드는 추측하지 않는다. 첫 호출 응답을 fixture로 저장하고 그 fixture 기준으로 매핑한다.

**Interfaces:**
- Produces (types.ts):
  - `type LoanRule = Database['public']['Tables']['loan_rules']['Row']`, `type RegulatedArea = …['regulated_areas']['Row']`, `type LoanProduct = …['loan_products']['Row']`
  - `type BuyerType = 'first_time' | 'homeless' | 'one_house' | 'multi_house'`
  - `type AreaType = 'speculative_overheated' | 'adjustment_target' | 'speculation_zone' | 'land_transaction_permit'`
- Produces (rules.ts):
  - `buyerTypeOf(p: { ownedHouseCount: number; isFirstTime: boolean | null }): BuyerType` — 0채+생애최초 → `first_time`, 0채 → `homeless`, 1 → `one_house`, 2+ → `multi_house`.
  - `activeAreaTypes(regionCode: string, areas: RegulatedArea[], date: string): AreaType[]` — `region_code`가 대상 코드의 접두(시군구 5자리 지정 → 하위 동 포함; 앞자리 비교는 `regionCode.startsWith(area.region_code.replace(/0+$/, ''))`)이고 `effective_date ≤ date ≤ end_date(null=무기한)`.
  - `selectRule(rules: LoanRule[], ruleType: LoanRule['rule_type'], ctx: { date: string; price: number; buyerType: BuyerType; areaTypes: AreaType[]; regionCode: string | null; lenderType: 'bank' | 'non_bank' | 'policy' }): LoanRule | null`

selectRule 매칭 규칙(테스트가 다 고정하지 못하는 부분):
- 기간: `effective_date ≤ date` 이고 (`end_date` null 또는 `≥ date`).
- 가격: `price_min ≤ price < price_max` (null은 무제한).
- `buyer_type`: null, 같은 값, 또는 규칙이 `homeless`이고 대상이 `first_time`.
- `area_type`: null / `regulated`(areaTypes 비어있지 않음) / `non_regulated`(비어 있음) / 그 외는 areaTypes에 포함.
- `region_prefix`: null 또는 `regionCode.startsWith(prefix)`. regionCode가 null이면 prefix 있는 규칙 제외.
- 여러 개면 null이 아닌 조건 컬럼 수가 많은 것(구체적), 동률이면 `effective_date` 최신.

  - `type BudgetResult = { maxPrice: number; minRatePrice: number; maxRatePrice: number; loan: { amount: number; binding: 'ltv'|'loan_cap'|'dsr' }; ownFunds: number; costs: { acquisitionTax: number; brokerage: number; total: number }; products: Array<{ productId: number; provider: string; name: string; loanAmount: number; monthlyAtMin: number | null; monthlyAtMax: number | null; termYears: number }>; diagnoses: Diagnosis[]; ruleSources: string[] }`
  - `computeBudget(input: BudgetInput): BudgetResult`
  - `eligibleProducts(products: LoanProduct[], p: { date: string; price: number; annualIncome: number | null; buyerType: BuyerType; isNewlywed: boolean | null; hasNewborn: boolean | null; exclusiveAreaM2: number; ownFunds: number }): LoanProduct[]` — 기간 유효, `requires_*`, `income_max`, `house_price_max`, `exclusive_area_max`, `asset_max` 필터.
  - `DEFAULT_TERM_YEARS = 30` (상품 `max_term_years`가 null일 때)

알고리즘(시그니처로 결정되지 않는 부분):
- 자기자본 `ownFunds = cashAssets + extraFunds`.
- 가격 P에 대해 `loan(P, rate)` = `maxLoan(ltv=selectRule('ltv'), cap=selectRule('loan_cap'), dsr=maxPrincipalByDsr(dsr=selectRule('dsr'), stress=selectRule('stress_rate') ?? 0, rate))`. lenderType은 `'bank'`.
- `필요자금(P) = P − loan(P) + acquisitionTax(P).total + brokerageFee(P).fee`.
- 가격대별 한도가 계단식이라 단조성이 보장되지 않으므로 이분 탐색 대신 **50억에서 100만원 단위로 내려가며 처음으로 `필요자금 ≤ ownFunds`인 P**를 찾는다(5,000회, 충분히 빠름).
- `minRatePrice`/`maxRatePrice`: 적격 은행 상품의 `rate_min` 최솟값/`rate_max` 최댓값으로 각각 계산 → 예산 범위. `maxPrice = minRatePrice`.
- ltv 또는 dsr 규칙이 없으면 대출 0원으로 계산하고 `rule_missing` + `funds_only`. 소득 null/0이면 `missing_income`, 대출 0원.
- `houseCountAfter ≥ 2`면 `heavy_tax_possible`.
- `ruleSources`: 사용한 규칙 행의 `source` 중복 제거.
