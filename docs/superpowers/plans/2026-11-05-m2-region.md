# M2: 2단계 지역·생활 조건 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 수도권 아파트 매매 실거래가를 매일 적재하고, 사용자가 2단계(희망 지역·생활·거주 환경)를 저장하면 시군구별 중위 실거래가와 "내 예산으로 접근 가능한지"를 결정론적으로 보여주며, 에이전트가 그 결과를 기준일·TIP과 함께 설명한다.

**Architecture:** collector `jobs/transactions.py`가 PublicDataReader `TransactionPrice`로 수도권 시군구 × 최근 N개월을 받아 `transactions`에 `source_key` upsert하고 24개월 밖 행은 지운다. 집계는 Postgres RPC `region_price_stats`(중위가·건수·최근 거래일)가 하고, 툴 `get_region_prices`가 RPC 결과에 시군구별 `computeBudget().maxPrice`를 붙인다(규제지역별 LTV가 달라서 시군구마다 따로 계산). 2단계 폼은 `condition_sets`에 새 행을 넣는다(append-only).

**Tech Stack:** M1과 동일 — Next.js 16 App Router, zod v4, vitest, Supabase CLI(로컬)·pgTAP, Python 3.13 + uv + PublicDataReader 1.1.1.post2 + supabase-py + pytest, GitHub Actions.

**Spec:** `CLAUDE.md`("2단계. 희망하는 주거 환경 설정", 원칙 1~11), 로드맵 `docs/superpowers/plans/2026-11-03-roadmap.md`의 M2 항목과 결정 D1~D5.

**선행 조건:** PR #1(M1) 머지 여부를 사용자에게 확인한다. 머지됐으면 `main`에서 `feat/m2-region` 브랜치, 아니면 `feat/m1-budget` 위에 쌓는다. `DATA_GO_KR_SERVICE_KEY`(공공데이터포털 "국토교통부_아파트 매매 실거래가 상세 자료" 활용신청 키)가 없거나 무효면 Task 2 Step 1에서 멈추고 요청한다 — 그동안 Task 1 → 4 → 5를 먼저 진행할 수 있다.

## 용량 추정 (원칙 11)

- 행 수: 수도권 아파트 매매 연 ~18만~25만 건(서울·경기·인천 합계, 해제 포함 상한으로 25만) × 24개월 ≈ **최대 50만 행**.
- 행 크기: 힙 ~230B(튜플 헤더 24 + 컬럼 ~200, 단지명 한글 UTF-8 포함) + 인덱스 ~150B(pkey, `source_key` 유니크, `(region_code, deal_date)`) ≈ **~380B/행**. `complex_id` 인덱스는 M2 동안 전부 null이므로 Task 1에서 부분 인덱스(`where complex_id is not null`)로 바꿔 ~25MB를 뺀다.
- 합계: 50만 × 380B ≈ **~190MB**. 기존 데이터(regions 약 5만 행 등) ~20MB를 더해 ~210MB < 400MB.
- 저장 컬럼은 `transactions` 기존 컬럼만. 원본 응답(raw JSON/XML)과 도로명·등기일자·매도/매수자 구분 등은 저장하지 않는다.
- 검증: Task 3 Step 4에서 1개월 실제 적재 후 `bytes_per_row × 월 행 수 × 24`로 다시 계산한다. **250MB를 넘으면 원격 백필 전에 멈추고 사용자에게 알린다.**

## Review Focus

1. **같은 날 같은 단지·동·면적·층·금액 거래 2건** — 같은 `source_key`가 한 upsert 배치에 두 번 들어가면 Postgres가 `ON CONFLICT DO UPDATE command cannot affect row a second time`으로 배치 전체를 거부한다. transform이 배치 내 중복을 하나로 합치고 건수를 센다. (Task 2 `test_duplicate_keys_collapsed`)

- [ ] **Step 1: 실패하는 pgTAP 테스트 작성** — `supabase/tests/database/region_prices.test.sql`. 기존 `chat_usage.test.sql` 형식(`begin; select plan(N); … finish(); rollback;`). 준비: `delete from public.transactions;`, regions 행을 `on conflict (code) do nothing`으로 삽입 — `1100000000` 서울특별시(시도), `1168000000` 강남구, `1168010300` 강남구 개포동, `1165000000` 서초구, `4111000000` 수원시, `4111100000` 수원시 장안구, `4111112900` 장안구 동, `2611000000` 부산 중구. 거래일은 `(now() at time zone 'Asia/Seoul')::date - n`으로 상대 지정. 단언:

```sql
select set_eq($$select sigungu_code from public.capital_sigungu where sigungu_code in ('11680','41110','41111','26110')$$,
  array['11680','41111'], '구가 있는 시(41110)와 수도권 밖(26110)은 제외');
-- 개포동 아파트 5억·7억·9억(중개, 유효) + 1억(해제) + 2억(직거래) + 30억(400일 전) → 중위 7억, 3건
select results_eq($$select median_price, deal_count from public.region_price_stats('11680','apartment',12)$$,
  $$values (700000000::bigint, 3)$$, '해제·직거래·기간 밖 제외 중위가');
-- 같은 단지 6억·8억 두 건만 있는 서초구 → 7억 (짝수 건 평균)
select is((select median_price from public.region_price_stats('11650','apartment',12)), 700000000::bigint, '짝수 건 중위');
select is((select count(*)::int from public.region_price_stats('11','apartment',12)), 2, '시도 접두사는 시군구별 행');
select is((select deal_count from public.region_price_stats('11680','apartment',12, 80, 90)), <80~90㎡ 건수>, '면적 필터');
select is((select sigungu_name from public.region_price_stats('11680','apartment',12)), '서울특별시 강남구', '이름');
select throws_ok($$select * from public.region_price_stats('1168','apartment',12)$$, '22023', null, '접두사는 2 또는 5자리');
select throws_ok($$select * from public.region_price_stats('11680','apartment',0)$$, '22023', null, 'months 1~24');
```
